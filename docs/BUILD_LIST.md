# Astra — Build List

Every buildable feature from `Astra-PRD.pdf` (Draft v1.1), with current status and a definition of done, followed by the **Build order** — the dependency-ordered queue of steps the autonomous pipeline works through. Update the Status columns as work lands; a feature is only **Done** when its definition of done is observably true in the app.

**Statuses:** `Not started` → `In progress` → `Built` (code complete, merged) → `Done` (definition of done verified on both platforms). Build-order steps also use `Blocked` (waits on a decision only Tristen can make).
**Phases:** P0 = Phase 1 (log and share), P1 = Phase 2 (programs and groups), P2 = Phase 3 (gyms and recovery). All ship in the first release; the phase sets build order only.

## Build order

The queue the autonomous pipeline works through (`docs/PIPELINE.md`). One row = one step = one planner run + one builder run on one branch, whose plan file is `docs/feature_plans/<Branch>.md`. `automation/scripts/pipeline.mjs next` picks the **first `Not started` step whose every `Depends on` step is `Built` or `Done`**; it skips `Blocked` steps and steps whose dependencies aren't met, and refuses to run while any step is `In progress` or the picked step's branch already exists. `pipeline.mjs lint` checks this table against the feature tables above (every ID in Covers exists, every unfinished feature is covered by some step, dependencies point at earlier steps, branches are unique).

How to read a row: **Covers** lists the feature IDs the step advances — `(part)` means the feature needs more than this step. **Depends on** names steps that must be merged first. **Scope** says what gets built and ends with the step's own definition of done. At merge (Gate 2) Tristen flips the step to `Built`, and flips each covered feature's Status in the tables above as its definition of done becomes true. Phase order holds (P0 → P1 → P2) except where a row says a small P1 item rides on a P0 step because its column already exists.

**Not steps:** NFR-11 — both-platform parity is Tristen's device verification that flips each feature from `Built` to `Done`; it is never a pipeline run.
